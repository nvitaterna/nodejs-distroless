# Contributing

Thanks for helping out! Issues and pull requests are welcome.

## Before you start

- **Bugs and requests:** [open an issue](https://github.com/nvitaterna/nodejs-distroless/issues/new/choose) first for anything larger than a small fix, so we can agree on the approach.
- **Security issues:** don't open a public issue; see [SECURITY.md](SECURITY.md).
- **New Node.js versions** are added automatically by the hourly `get-new-versions` workflow. Please don't edit `versions.json` by hand.
- **Dependency updates** (Ubuntu, Chisel, apt packages, GitHub Actions, npm) come from Renovate.

## Repository layout

See [How it is built](README.md#how-it-is-built) in the README for what each part does. In short:

| Path | What |
|---|---|
| `Dockerfile` | the base (Chisel rootfs), release and debug images |
| `test/check.js` | smoke test run inside every built image |
| `test/native-addons/` | sharp and better-sqlite3, installed in `node:<version>` and loaded in the image (PR builds) |
| `versions.json` | the versions and tags to publish, generated by `tools/version-info` |
| `tools/version-info/` | TypeScript tool that builds the version list from nodejs.org |
| `.github/workflows/` | PR builds, publishing, scans, version updates |
| `scripts/` | helper scripts, e.g. `image-sizes.sh` |

## Building and testing an image

You need Docker with Buildx. Building the base compiles Chisel, so the first build takes a few minutes.

```sh
docker build --build-arg NODE_VERSION=22.23.4 -t nodejs-distroless:22.23.4 .
docker run --rm -v "$PWD/test/check.js:/check.js:ro" -e EXPECTED_NODE_VERSION=22.23.4 \
  nodejs-distroless:22.23.4 /check.js
```

The native addon test installs sharp and better-sqlite3 with `npm ci` in the official `node:22.23.4` image and loads them in yours. Each addon also runs in `node:22.23.4` first; if it fails there too, the addon itself is broken on that release and is skipped with a warning:

```sh
test/native-addons/run.sh nodejs-distroless:22.23.4 22.23.4   # add linux/arm64 for the other arch
```

The debug variant is the `debug` target:

```sh
docker build --target debug --build-arg NODE_VERSION=22.23.4 -t nodejs-distroless:22.23.4-debug .
```

To build for the other architecture, add `--platform linux/arm64` (or `linux/amd64`). This needs QEMU emulation, e.g. through Docker Desktop or `docker run --privileged --rm tonistiigi/binfmt --install all`.

If you change what goes into the image, add a check to `test/check.js` for it.

## Working on `tools/version-info`

Requires Node.js and [pnpm](https://pnpm.io/):

```sh
cd tools/version-info
pnpm install
pnpm lint && pnpm test
pnpm build && node dist   # prints the version list as JSON
```

## Pull requests

- Keep each PR focused on one change.
- Use [Conventional Commits](https://www.conventionalcommits.org/) for the PR title (`fix: ...`, `feat: ...`, `docs: ...`, `ci: ...`, `chore: ...`). PRs are squash-merged, so the title becomes the commit message.
- CI builds the oldest and newest version of each Node.js line on amd64 and arm64, runs the smoke test and scans the images. All checks must pass before merging.
- Workflow changes are linted with [actionlint](https://github.com/rhysd/actionlint). You can run it locally: `docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest`.
